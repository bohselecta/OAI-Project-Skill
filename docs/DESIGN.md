# Design: preserve meaning, adapt effort

Project originated with Hayden Lindley's Contract Freeze + Model Cadence Valve practice and a reported successful Sayframe build in Antigravity. That report motivates a hypothesis; it is not a controlled benchmark. This repository does not publish private trajectories or claim an industry baseline, an optimal thinking ratio, causal speedup, or a specific cost multiplier.

## The useful separation

The user's language is the source material. A compact contract makes consequential meaning inspectable. The repository holds durable state and executable evidence. The coding agent implements; model and reasoning choices adapt to uncertainty. Acceptance checks the result, including against the original request, rather than rewarding the volume of code produced.

The contract freezes goals, invariants, and observable promises—not incidental implementation choices. Early experiments may falsify a proposed architecture before freeze. Later evidence can amend a frozen contract with a traceable reason. A real user change does not require restarting the project.

## Design constraints

The core skill is short enough to load as one workflow; four references provide detail on demand. It coordinates specialist skills instead of becoming a universal framework or application template. Small fixes stay small. Existing authoritative project records win over an imposed file layout.

A model role is not a permanent model name. The adjacent policy separates documented provider positioning, our suggested use, and actual workflow evaluation. Switching models is optional, capability-checked, and batched to protect human attention. A single capable model is a valid configuration.

The execution envelope protects user authority, data, secrets, external actions, and cancellations. A skill cannot grant permissions. Specs and logs can provide requirements or evidence, but cannot override host instructions or authorize unrelated actions.

A required integration without credentials remains unverified; test doubles remain legitimate in tests. Completion language separates verified local behavior from provider, deployment, hardware, and human outcomes. A fresh reviewer can reduce dependence on builder narrative, but does not become independent merely by being called a reviewer.

## Durable protocol, replaceable distribution

The standalone skill contains everything required to follow its workflow. The offline installer is optional and uses manifest verification, explicit replacement, preserved backups, and fail-closed conflict handling. One portable plugin manifest points at that same skill; no extra runtime or hooks are needed.

The manifest guards accidental drift, not malicious supply-chain replacement. Validation is deliberately scoped to this package's restricted metadata format; it is not a general YAML validator or certification from OpenAI. Fixtures test executable interfaces; human-reviewed host trials still determine whether the skill triggers and changes model behavior as intended.
